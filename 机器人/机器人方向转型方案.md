## 0. 一句话结论

**你的底子比大多数转行者好得多**：C++ / Qt 全家桶 / Linux / UDP 组播多线程 / OpenCV / OSG+osgEarth 三维渲染 / AFSIM 二次开发 —— 这套组合在机器人行业里直接对应「上位机 + 仿真 + 集成」三类岗位。

你真正缺的只有三块：

1. **ROS 2 生态**（工程骨架，目前是 0，但这是最容易补的一块，2 个月能到“能干活”）
2. **机器人学数学**（坐标变换 / 正逆解 / 轨迹 / 控制律——你是“会画图”，还没到“会控位姿”）
3. **一条“真机闭环”的证据链**（简历里全是软件层，没有任何“我让物理世界动了”的记录）

补齐这 3 块 + 2 个可演示项目 → 达到 1–3 年机器人软件岗的面试线（约 ¥15–25K/月，一线城市）。**不需要读研，也不需要转算法**。

## 2. 目标定位：四条路线，选一条主攻 + 一条纵深

| 路线 | 岗位名称（JD 常见） | 与你的匹配度 | 门槛 | 天花板 | 建议 |
|---|---|---|---|---|---|
| **① 机器人上位机 / 系统集成** | 机器人软件工程师、上位机开发、HMI、系统集成 | ⭐⭐⭐⭐⭐ | 低 | 中 | **主攻**（最快上岸） |
| **② 机器人仿真 / 数字孪生** | 仿真平台工程师、视景仿真、数字孪生、HIL 半实物仿真 | ⭐⭐⭐⭐⭐ | 中 | 中高 | **主攻**（差异化最强，竞争者最少） |
| **③ 运动控制 / 机器人应用** | 机器人应用工程师、运动控制、ros2_control、EtherCAT | ⭐⭐⭐ | 中高（要补数学） | 高 | **纵深**（1 年后转） |
| **④ 具身智能工程** | 具身智能工程师、数据采集/仿真环境、VLA 部署 | ⭐⭐ | 高（要 ML） | 很高 | 加分项，做一个 demo 即可 |

**为什么强烈推荐 ①+②**：你现在做的是航空**视景仿真 + 想定系统 + 上位机**。平移到机器人就是「仿真平台 + 机器人上位机 + 数据链路」。这个组合的人才供给极少——会 Qt 的一堆，会 MoveIt 的一堆，**同时懂三维引擎、仿真协议、多线程实时数据流的很少**。

**不要**一上来冲 SLAM / 感知算法：那需要硕士 + 论文 + C++ 数值优化功底，投入产出比对你最差。

## 3. 「达到什么水平」——可验证的等级标尺

先定义标尺（面试官就是这么打分的）：

| 等级 | 含义 | 判据 |
|---|---|---|
| L0 | 没接触 | — |
| L1 | 跑过教程 | 能复现官方 demo，说得出大概流程 |
| L2 | 能干活 | 在现成框架上改功能、定位 bug、看懂别人的包 |
| L3 | 能独立负责 | 从需求到上线，能选型、能写文档、能兜底、能估工时 |
| L4 | 能定标准 | 能改框架源码、能设计方案、能带人 |

> 社招 **1–3 年要 L2+**，**3–5 年要 L3**。你现在整体在 L1–L2 之间（因为没碰过 ROS），但你的“工程素养”其实已接近 L3，只是没有机器人语境。

## 4. 12 个月路线图（按每周 ~20 h：工作日晚 1.5 h × 5 + 周末 8 h）

### 6.2 Before / After 示例

**Before（现在）**
> 项目名称：基于 OSGEARTH 的地图引擎开发
> 技术栈：QT、OSGEARTH、OSG、UDP、SVG、QPainter、QThread
> 职责：1、加载二维地图图片并加载 svg 图片。2、让 svg 图片根据发来的航路运动。3、用 QT 绘制其他界面例如标识牌。4、利用碰撞检测获取被加载在地图上的实体信息

**After（机器人版）**
> **分布式仿真平台 · 二维态势与地图引擎**（Qt 5 / OSG + osgEarth / C++17）
> · 基于 osgEarth 构建矢量地图渲染管线，支持栅格底图 + SVG 符号动态加载，单场景 200+ 实体时保持 60 FPS；
> · 实现「航路协议 → 场景图位姿」的实时映射，通过 UDP 组播接收 50 Hz 位姿流，端到端可视化延迟 < 50 ms；
> · 基于场景图包围体实现碰撞检测与实体拾取，支撑点击查询与信息面板联动；
> · 采用 QThread + 双缓冲将网络线程与渲染线程解耦，消除卡顿（渲染线程零阻塞）。

**为什么这么改**：把“功能清单”变成“**坐标链路 + 数据流 + 性能指标**”，这三样正是机器人面试官关心的。

**Before**
> 项目名称：基于 AFSIM 的二次开发 … 通过组播加 UDP 的方式发送数据到模拟器与三维

**After**
> **AFSIM 仿真引擎集成（含自定义插件）**：按接口协议实现与模拟器、三维端的分布式数据交换（UDP 组播、结构体序列化），支持想定数据导入导出（SQLite 持久化）；编写 AFSIM 自定义插件扩展仿真行为；负责平台侧 200 Hz 状态数据同步与冲突消解。
> *（面试时这样讲：这套“仿真引擎 + 插件 + 实时数据总线”的架构，和 Gazebo/Isaac 里写 plugin + 传感器数据流是一回事。）*

## 9. 九条“别做”的忠告

1. **别一上来学 SLAM / 深度学习**。岗位少、门槛高（硕士+论文），对你投入产出比最差。
2. **别只跑 tutorial**。跑完 `demo.launch.py` 不等于会；每个教程都要“删掉 launch 自己配一遍”。
3. **别开十个仓库**。同时开 3 个以上必然烂尾。
4. **别买贵硬件**。真机是为了“闭环”，不是为了“好看”。
5. **别把技能表写成愿望清单**。写了的每一条都要能被追问三层。
6. **别丢掉嵌入式那一段**。V1.1 删掉 STM32/FreeRTOS 是策略失误，机器人行业正缺“上下位机通吃”。
7. **别脱离现在的工作**。你手里的 AFSIM/OSG/组播，是别人拿不到的训练场；把“仿真 + 实时数据链路”这套语言练熟，比换赛道从零开始更划算。
8. **别只投“机器人公司”**。数字孪生、工业软件、AGV/AMR、军工仿真、半导体设备（也是大量 ROS/运动控制）都要人。
9. **别等准备好再投**。准备到 70% 就开始面，面试反馈是最高效的学习清单。
